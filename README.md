# turbobt
A next generation Bittensor SDK, for Python 3.

# Wallets

Use the native wallet from Bittensor 11:

```python
from bittensor.wallet import Wallet
from turbobt import Bittensor

wallet = Wallet(name="validator", hotkey="default", path="~/.bittensor/wallets")
client = Bittensor("finney", wallet=wallet)
```

Legacy keyfiles and SR25519 wallets generated by the Bittensor 10.5 and 11 CLIs are
supported without rewriting the files. The standalone `bittensor-wallet` package is
no longer a dependency. Code constructing keypairs should import `Keypair` from
`bittensor.keyfiles`.

The default `alice_wallet` fixture creates v11 wallet files in a pytest temporary
directory using `bittensor.wallet` and the well-known `//Alice` derivation URI.
The general test suite therefore exercises the native format while retaining the
Alice addresses expected by the mocked chain responses. No wallet files are
stored in the repository.

`test_wallet_compatibility.py` covers only legacy formats. Its module-scoped
`generated_legacy_wallet` fixture generates fresh wallets using isolated,
version-pinned producers:

| Legacy format | Producer |
|---|---|
| Without `cryptoType` | bittensor-wallet 4.0.1 |
| Bittensor 10.5 CLI | bittensor 10.5.0, bittensor-cli 9.22.0, bittensor-wallet 4.1.0 |

Bittensor 10.5 ships a separately versioned 9.x CLI. The fixture invokes its
`wallet new-coldkey` and `wallet new-hotkey` commands with encryption disabled.
Expected addresses come from the generated JSON, with no fixed keys or addresses
in the compatibility tests. Both coldkey and hotkey signatures are independently
verified through the public extrinsic submission API, and files must remain
unchanged. Only RPC transport is mocked.

```sh
uv sync --dev --locked
uv run pytest tests
# Legacy compatibility only:
uv run pytest tests/test_substrate/test_pallets/test_wallet_compatibility.py
```

Legacy compatibility tests require `uv` on PATH and package-index access on the
first run; subsequent runs can reuse uv's package cache. Producers use the test
interpreter's Python version and run with a timeout and closed stdin. Generation
failures fail the tests rather than silently skipping coverage.

# Releasing

Building and deploying to pypi is done via Gtihub Actions. To release a new version do:

```
git tag vX.Y.Z
git push origin vX.Y.Z
```
